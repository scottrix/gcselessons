Lesson 1: Bubble Sort & Insertion Sort

Duration: 50 minutes

Starter Activity (5 minutes)

Sorting Cards

Give students 6 playing cards face up in random order. Ask them to sort ascending. Observe their natural algorithm - usually insertion-like. Discuss steps taken.

Main Content (35 minutes)

Teaching Notes:
Cover two simple O(n²) sorts:
  • Bubble Sort: Repeatedly swap adjacent elements if wrong order. Larger elements "bubble" to end.
  • Insertion Sort: Build sorted portion left-to-right. Insert each new element into correct position in sorted portion.
  • Both: Best O(n) for nearly sorted, Average/Worst O(n²), Space O(1)
  • Insertion sort generally faster in practice due to fewer swaps
Bubble Sort Pseudocode:
FUNCTION bubbleSort(array):
    n = length(array)
    FOR i FROM 0 TO n - 2:
        swapped = FALSE
        FOR j FROM 0 TO n - 2 - i:
            IF array[j] > array[j + 1]:
                SWAP array[j], array[j + 1]
                swapped = TRUE
        IF NOT swapped:
            BREAK
END FUNCTION
Insertion Sort Pseudocode:
FUNCTION insertionSort(array):
    FOR i FROM 1 TO length(array) - 1:
        key = array[i]
        j = i - 1
        WHILE j >= 0 AND array[j] > key:
            array[j + 1] = array[j]
            j = j - 1
        array[j + 1] = key
END FUNCTION
Python Implementation:
def bubble_sort(arr):
    n = len(arr)
    for i in range(n - 1):
        swapped = False
        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True
        if not swapped:
            break
    return arr

def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr

# Test
data = [64, 34, 25, 12, 22, 11, 90]
print(bubble_sort(data.copy()))      # [11, 12, 22, 25, 34, 64, 90]
print(insertion_sort(data.copy()))   # [11, 12, 22, 25, 34, 64, 90]

Common Misconception

"Bubble sort is the standard sorting algorithm"

Bubble sort is taught for conceptual understanding. Real systems use Timsort (Python), Dual-Pivot Quicksort (Java), or Introsort (C++) - all O(n log n). Bubble sort is rarely used in production.

Differentiation

Support (SEN/Lower Ability):
Use physical cards for trace. Provide step-by-step trace tables with columns for pass, comparison, swap, array state. Limit to 5 elements.
Stretch (Higher/Gifted):
Implement optimised bubble sort (track last swap position). Code recursive insertion sort. Compare swap count vs comparison count. Research shell sort as generalised insertion sort.

Plenary (5 minutes)

Trace Race

Pairs trace both sorts on [5, 2, 8, 1]. First correct trace wins. Discuss: which made fewer comparisons? Which fewer swaps?

Assessment Criteria

  • Got it: Traces both correctly, writes pseudocode, explains O(n²) vs O(n) best case
  • Getting there: Understands concept but trace errors or confusion between algorithms
  • Not yet: Cannot explain either algorithm or confuses with searching

Lesson 2: Merge Sort - Divide and Conquer

Duration: 50 minutes

Starter Activity (5 minutes)

Divide & Conquer

Analogy: Sorting a deck of cards. Split in half, sort each half, then merge. How to merge two sorted piles? Always take smaller top card.

Main Content (35 minutes)

Teaching Notes:
Merge Sort - O(n log n) guaranteed:
  • Divide: split array in half recursively until single elements
  • Conquer: single element is trivially sorted
  • Combine: merge two sorted arrays into one sorted array
  • Time: O(n log n) best/average/worst - consistent
  • Space: O(n) auxiliary - not in-place
  • Stable sort (preserves order of equal elements)
Merge Sort Pseudocode:
FUNCTION mergeSort(array):
    IF length(array) <= 1:
        RETURN array
    mid = length(array) // 2
    left = mergeSort(array[0:mid])
    right = mergeSort(array[mid:])
    RETURN merge(left, right)

FUNCTION merge(left, right):
    result = []
    i = j = 0
    WHILE i < length(left) AND j < length(right):
        IF left[i] <= right[j]:
            APPEND left[i] TO result
            i = i + 1
        ELSE:
            APPEND right[j] TO result
            j = j + 1
    APPEND remaining elements
    RETURN result
Python Implementation:
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# Test
data = [64, 34, 25, 12, 22, 11, 90]
print(merge_sort(data))  # [11, 12, 22, 25, 34, 64, 90]
Merge Sort Trace

Array: [38, 27, 43, 3, 9, 82, 10]
Divide: [38,27,43,3] [9,82,10] → [38,27] [43,3] [9,82] [10] → [38] [27] [43] [3] [9] [82] [10]
Merge: [27,38] [3,43] [9,82] [10] → [3,27,38,43] [9,10,82] → [3,9,10,27,38,43,82]

Differentiation

Support (SEN/Lower Ability):
Provide recursion tree diagram. Focus on merge step with physical cards. Use merge helper function template.
Stretch (Higher/Gifted):
Implement bottom-up (iterative) merge sort. Discuss space optimisation with single auxiliary array. Research natural merge sort for nearly sorted data.

Plenary (5 minutes)

Why O(n log n)?

Tree height = log₂(n) levels. Each level merges all n elements = O(n) work per level. Total = O(n log n).

Assessment Criteria

  • Got it: Explains divide/conquer, traces merge, writes pseudocode, states O(n log n)
  • Getting there: Understands merging but struggles with recursion or pseudocode
  • Not yet: Cannot explain merge step or confuses with quick sort

Lesson 3: Quick Sort & Algorithm Comparison

Duration: 50 minutes

Starter Activity (5 minutes)

Pivot Partitioning

Array: [3, 7, 2, 9, 1, 5]. Choose pivot 5. Partition: elements < 5 left, > 5 right. Result: [3,2,1,5,7,9]. Pivot now in correct final position.

Main Content (35 minutes)

Teaching Notes:
Quick Sort - O(n log n) average, O(n²) worst:
  • Choose pivot (first, last, middle, random, median-of-three)
  • Partition: rearrange so elements < pivot left, > pivot right
  • Recursively sort left and right partitions
  • In-place (O(log n) stack space)
  • Unstable sort
  • Worst case: already sorted + poor pivot choice
Quick Sort Pseudocode:
FUNCTION quickSort(array, low, high):
    IF low < high:
        pivotIndex = partition(array, low, high)
        quickSort(array, low, pivotIndex - 1)
        quickSort(array, pivotIndex + 1, high)

FUNCTION partition(array, low, high):
    pivot = array[high]  # Lomuto: last element as pivot
    i = low - 1
    FOR j FROM low TO high - 1:
        IF array[j] <= pivot:
            i = i + 1
            SWAP array[i], array[j]
    SWAP array[i + 1], array[high]
    RETURN i + 1
Python Implementation:
def quick_sort(arr, low=0, high=None):
    if high is None:
        high = len(arr) - 1
    if low < high:
        pi = partition(arr, low, high)
        quick_sort(arr, low, pi - 1)
        quick_sort(arr, pi + 1, high)
    return arr

def partition(arr, low, high):
    pivot = arr[high]
    i = low - 1
    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1

# Test
data = [64, 34, 25, 12, 22, 11, 90]
quick_sort(data)
print(data)  # [11, 12, 22, 25, 34, 64, 90]

Extended Evaluation Question

12-mark style question: "A student claims 'Quick sort is always the best sorting algorithm because it's O(n log n)'. Evaluate this statement. Discuss time complexity, space complexity, stability, and pivot selection."

Differentiation

Support (SEN/Lower Ability):
Use fixed pivot (last element). Provide partition trace template. Focus on concept not implementation details.
Stretch (Higher/Gifted):
Implement Hoare partition scheme. Discuss median-of-three pivot. Research introsort (hybrid quicksort/heapsort). Compare with Python's Timsort.

Plenary (5 minutes)

Pivot Choice Impact

Show: sorted array [1,2,3,4,5] with first-element pivot → O(n²). Random pivot → O(n log n) expected.

Assessment Criteria

  • Got it: Explains partitioning, traces quicksort, discusses pivot impact on complexity
  • Getting there: Understands concept but trace errors or misses worst case
  • Not yet: Confuses with merge sort or cannot explain partitioning

Lesson 4: Comparison, Stability & Exam Practice

Duration: 50 minutes

Starter Activity (5 minutes)

Sorting Algorithm Top Trumps

Create cards for each algorithm with stats: Time Best/Avg/Worst, Space, Stable? In-place? Students compare.

Main Content (35 minutes)

Teaching Notes:
Comprehensive comparison:
  • When to use each: small data → insertion, guaranteed O(n log n) → merge, general purpose → quick/heap
  • Stability matters for multi-key sorts (e.g., sort by surname then first name)
  • External sorting (large files) uses merge sort variants
  • Python's sorted() uses Timsort (hybrid merge/insertion)
Complete Comparison Table:

Exam Question

"A programmer sorts 500 student records by grade (A*-U) then by name. Which algorithm property is essential? Explain." Answer: Stability - preserves name order when grades equal.

Differentiation

Support (SEN/Lower Ability):
Provide completed comparison table. Use scenario cards: "Sort 10 numbers", "Sort 1M records", "Sort nearly sorted data".
Stretch (Higher/Gifted):
Research counting sort, radix sort (non-comparison O(n)). Discuss lower bound Ω(n log n) for comparison sorts. Implement hybrid sort.

Plenary (5 minutes)

Algorithm Selection

Scenarios: (a) Nearly sorted 1000 items → Insertion, (b) 1M random integers → Quick/Merge, (c) Linked list → Merge, (d) Memory constrained → Quick/Heap.

Assessment Criteria

  • Got it: Selects appropriate algorithm for scenario, justifies with complexity/stability
  • Getting there: Knows complexities but struggles to apply to scenarios
  • Not yet: Cannot differentiate algorithms or match to use cases

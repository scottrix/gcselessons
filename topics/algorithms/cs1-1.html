CS1.1: Searching Algorithms

Foundation Higher All Boards

Linear search, binary search, algorithm design, pseudocode, Python implementation, time complexity comparison

Lesson Overview

Estimated Lessons: 3
Tier: Foundation and Higher
Duration: 50 minutes per lesson
Exam Boards: AQA, Edexcel, OCR, WJEC

Lesson 1: Linear Search & Algorithm Design

Duration: 50 minutes

Starter Activity (5 minutes)

Finding a Book

Ask: "How would you find a specific book on an unsorted shelf vs a sorted shelf?" Discuss: unsorted = check each book (linear), sorted = check middle, eliminate half (binary).

Main Content (35 minutes)

Teaching Notes:
Cover linear search algorithm for unsorted data:
  • Sequential checking from first element
  • Best case: O(1) - found at first position
  • Worst case: O(n) - found at last or not found
  • Average case: O(n/2) ≈ O(n)
  • Works on ANY data (sorted or unsorted)
Use concrete examples with arrays/lists of numbers and strings.
Linear Search Pseudocode:
FUNCTION linearSearch(array, target):
    FOR i FROM 0 TO length(array) - 1:
        IF array[i] == target:
            RETURN i
    RETURN -1
END FUNCTION
Python Implementation:
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1

# Test
numbers = [64, 34, 25, 12, 22, 11, 90]
print(linear_search(numbers, 22))  # Output: 4
print(linear_search(numbers, 100)) # Output: -1

Common Misconception

"Linear search is always slow"

For small datasets (<50 items) or unsorted data, linear search is perfectly efficient and simpler to implement. Binary search requires sorted data which takes O(n log n) to sort first.

Differentiation

Support (SEN/Lower Ability):
Provide trace table template. Use small arrays (5-6 elements). Step through manually with highlighter. Focus on understanding the loop structure.
Stretch (Higher/Gifted):
Implement linear search for 2D arrays. Compare with Python's built-in list.index() and in operator. Discuss sentinel linear search variant.

Plenary (5 minutes)

Trace Table Practice

Given array [12, 7, 9, 3, 15], trace linear search for target 9. Show index, value, comparison, result at each step.

Assessment Criteria

  • Got it: Can trace linear search, write pseudocode, explain time complexity
  • Getting there: Can describe linear search but struggles with pseudocode or trace tables
  • Not yet: Cannot explain how linear search works or confuses with binary search

Lesson 2: Binary Search & Efficiency

Duration: 50 minutes

Starter Activity (5 minutes)

Guess the Number

Play "Guess my number 1-100" using binary search strategy. Show how 7 guesses max vs up to 100 for linear. Connect to log₂(100) ≈ 7.

Main Content (35 minutes)

Teaching Notes:
Cover binary search for SORTED data only:
  • Divide and conquer: check middle, eliminate half
  • Precondition: data MUST be sorted
  • Best case: O(1) - found at middle
  • Worst case: O(log n)
  • Average case: O(log n)
Show visual representation of search space halving.
Binary Search Pseudocode (Iterative):
FUNCTION binarySearch(array, target):
    low = 0
    high = length(array) - 1
    WHILE low <= high:
        mid = (low + high) // 2
        IF array[mid] == target:
            RETURN mid
        ELSE IF array[mid] < target:
            low = mid + 1
        ELSE:
            high = mid - 1
    RETURN -1
END FUNCTION
Python Implementation:
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

# Test (array MUST be sorted)
numbers = [11, 12, 22, 25, 34, 64, 90]
print(binary_search(numbers, 22))  # Output: 2
print(binary_search(numbers, 100)) # Output: -1
Trace Table: Binary Search

Array: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], Target: 23
Step 1: low=0, high=9, mid=4, arr[4]=16 < 23, low=5
Step 2: low=5, high=9, mid=7, arr[7]=56 > 23, high=6
Step 3: low=5, high=6, mid=5, arr[5]=23 == target, RETURN 5

Extended Evaluation Question

12-mark style question: "Compare linear search and binary search. Discuss time complexity, preconditions, and when each is appropriate. Include Big O notation in your answer."

Guide students through: AO1 (knowledge of both algorithms), AO2 (application to scenarios), AO3 (analysis of trade-offs). Use PEEL structure.

Differentiation

Support (SEN/Lower Ability):
Provide pre-drawn search trees. Use number line visual. Focus on iterative version first. Give partially completed trace tables.
Stretch (Higher/Gifted):
Implement recursive binary search. Discuss mid = low + (high - low) // 2 to prevent overflow. Compare with bisect module. Analyse binary search on rotated sorted array.

Plenary (5 minutes)

Algorithm Choice

Scenario cards: (a) Find student ID in unsorted list of 30, (b) Find word in dictionary of 50,000 words, (c) Find highest score in unsorted array. Students choose algorithm and justify.

Assessment Criteria

  • Got it: Can trace binary search, write pseudocode, explain O(log n), identify when to use each
  • Getting there: Understands concept but trace table errors or confusion with preconditions
  • Not yet: Cannot explain binary search or attempts on unsorted data

Lesson 3: Comparison, Big O & Exam Practice

Duration: 50 minutes

Starter Activity (5 minutes)

Big O Matching

Match algorithms to complexities: Linear Search O(n), Binary Search O(log n), Bubble Sort O(n²), Merge Sort O(n log n). Discuss what n represents.

Main Content (35 minutes)

Teaching Notes:
Compare both algorithms comprehensively:
  • Time complexity comparison table
  • Space complexity: both O(1) iterative
  • Preconditions: linear = none, binary = sorted
  • Real-world: databases use binary search trees (B-trees)
  • Hybrid approaches: interpolation search, exponential search
Comparison Table:

PreconditionNoneData must be sorted
Best CaseO(1)O(1)
Average CaseO(n)O(log n)
Worst CaseO(n)O(log n)

Exam-Style Question

"A programmer needs to search a list of 1000 sorted integers. Explain why binary search is more appropriate than linear search. Calculate the maximum number of comparisons for binary search."
Answer: log₂(1000) ≈ 10 comparisons max vs 1000 for linear.

Differentiation

Support (SEN/Lower Ability):
Provide comparison table pre-filled. Use smaller numbers (n=16, log₂(16)=4). Focus on practical examples not theory.
Stretch (Higher/Gifted):
Derive O(log n) mathematically. Discuss space complexity of recursive binary search (O(log n) call stack). Research lower bound proof for comparison-based search.

Plenary (5 minutes)

One-Minute Paper

Write: (1) When would you use linear search over binary? (2) What is the maximum comparisons for binary search on 1,000,000 items?

Assessment Criteria

  • Got it: Compares algorithms accurately, calculates log₂(n), chooses appropriately
  • Getting there: Knows binary is faster but cannot explain why or calculate comparisons
  • Not yet: Confuses time complexities or preconditions

Homework Suggestions

  • Implement both searches in Python with a menu-driven interface
  • Create a visual animation of binary search using turtle graphics
  • Complete past paper questions on searching algorithms
  • Research: How do real databases (SQL) implement searching? (B-trees)
